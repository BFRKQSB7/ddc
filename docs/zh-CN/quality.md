# ddc 质量指标

ddc 如何度量反编译质量、当前版本处于什么水位。所有数字可用
`tests/scripts/quality-report.sh` 复现。

## 指标定义

**E1——编译错误数（金标准门）。** 反编译产物用平台 `javac`
（android.jar + 补充库，跨版本同一 classpath）编译，错误数是首要
质量指标：反编译代码必须能编译。其内部分三类：

- `env:missing-package`——公开 android.jar 之外的 SDK 类
  （org.conscrypt、coil 等），DEX 侧不可修，对比时按 `ddc` 列剔除；
- 幻影类——R8 删类留引用，DEX 无定义可发射，语料地面；
- 其余——ddc 自身的输出质量，发版不得回归、质量轮持续压低的部分。

**S1——输出行数。** 全语料发射的 `.java` 总行数。同等错误数下越低
越好：寄存器噪声拷贝、`x = e; return x` 尾巴、`while(it.hasNext())`
循环等编译器产物由 cure 源码级 pass 语义保持地坍缩。

**S2——结构简化度**（按文件采样，cure `--stats`）：AST 节点数与
判定点（圈复杂度代理）前后对比——度量真结构工作，对格式化免疫。

**D1——确定性。** 两次完整运行必须逐字节一致（0-diff），每次发版
必查。

**P1——墙钟时间。** 每语料端到端反编译时间，冷机双跑取中值。
cure pass 在大语料上约等于反编译本身的成本（~2×）；`--no-cure`
以放弃 S1/S2 收益换速度。

## 当前水位（2026-10-11，四语料 battery）

每次发版都过门的四个公开 APK 语料：

| 语料 | 文件数 | 错误数 (E1) | vs v0.1.27 | 行数 (S1) | vs 无 cure |
|---|---|---|---|---|---|
| reqable | 5,579 | **317** | −66 | 607,038 | **−15.1%** |
| weibo | 110,525 | **3,622** | −66 | 15,472,863 | −16.0% |
| lark | 118,502 | **1,034** | −5 | 17,321,592 | −16.8% |
| weixin | 239,600 | **3,674** | −8 | 21,777,774 | −13.7% |
| **合计** | **474,206** | **8,647** | **−148** | **5,520 万** | **−15.3%** |

（v0.1.27 = 上一发版基线，同一语料与 classpath 实测；无 cure =
当前二进制 `--no-cure`，隔离源码级 pass 的贡献。）

结构简化采样（reqable，cure stats）：28,184 次编辑、AST 节点
−4.1%、判定点 −4.5%、解析失败 0/5,579。

## 版本对版本（E1，同语料同方法）

| 状态 | 错误数 | 说明 |
|---|---|---|
| v0.1.27（无 cure） | 8,795 | 上一发版，同语料实测 |
| + cure 集成 | 8,748 | 附加式源码级 pass（cure 侧 7 个正确性守卫） |
| + 退役 4 个 IR pass | 8,725 | 尾 return/三元/末端死赋值/xor → cure 吸收（parity，ddc 净减 360 行） |
| + 遮蔽成员逃逸 | **8,647** | JLS 6.4.2 静态导入逃逸（reqable cannot-find:变量 103 → 5） |

本段合计：**错误 −148（−1.7%）、输出行数 −15.3%、ddc 源码 −360 行**。
同一门上更长的弧线（早期语料组合略不同）：26,672（2026-09）→
8,777（v0.1.25）→ 8,647。

## 已知地面（不计为可修）

- `env:missing-package`——battery 全程 1,380；
- 幻影类——R8 删类引用（weibo b2×84 类、weixin ~1.5k cannot-find:类
  由此主导）；
- 局部变量 vs 导入简单名捕获（weixin +2）——逃逸机制在渲染点看
  不到局部变量。

## 性能（P1）

| 语料 | 反编译（含 cure） | cure 关闭 |
|---|---|---|
| reqable（36 MB） | 0.9 s | 0.4 s |
| weibo（185 MB） | 23.4 s | 10.3 s |

cure pass 是反编译后的最大单项成本（每文件 parse → 不动点简化 →
print，跑在类 worker 线程内）。`--no-cure` 供延迟敏感的批量场景。

## 复现

```sh
tests/scripts/quality-report.sh <apk>...   # 每语料 E1 + S1
tests/scripts/errtax.py <sweep-dir>        # 错误族分解
```

双跑 0-diff 与 `cargo test` 是每次发版门的一部分。
